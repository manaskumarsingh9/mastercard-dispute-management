# Dispute Management Dashboard Frontend

## What & Why
Build a React + Vite frontend dashboard using **Ant Design** for the existing Spring Boot dispute management backend. The dashboard gives issuers a professional case management view of transaction disputes, modeled after the reference chargeback management UI (see `attached_assets/image_1773864202632.png`). The frontend connects to the existing `/api/disputes` and `/api/mastercard` backend endpoints.

## Done looks like
- A polished, enterprise-style dashboard built with **React** and **Ant Design** components, with a left sidebar navigation (Dashboard, Active Disputes, Settled Cases, Settings)
- Main content area showing a "Dispute Management" view with:
  - Summary stats bar (total disputes, status counts, enrichment indicators)
  - Filter/search bar for filtering by Chargeback ID, Transaction ID, etc.
  - Tabs for dispute categories (e.g., Open, Represented, Not Represented)
  - Ant Design Table with columns matching the reference: Case/Chargeback ID, Type, Amount, Due Date, Enrichment %, Images count, Status (color-coded Ant Design Tags), Generated By
  - "View Details" action on each row opening a detail modal/drawer
- Bulk Enrichment button that is functional
- Full CRUD support for disputes from the UI (create, view, edit, delete)
- Mastercard API integration exposed in the frontend — ability to test connection, search transactions, file disputes, and view claim details via the existing `/api/mastercard` endpoints
- CORS properly configured on the Spring Boot backend so the React frontend can call it
- The Dispute entity enriched with additional fields to support the dashboard columns (amount, merchantName, dueDate, type, enrichmentPercent, imageCount, generatedBy)
- Seed/mock data pre-loaded so the dashboard looks populated on first load
- Frontend runs on port 5000 (webview), backend moved to port 8080
- Deployment configured for the combined app

## Out of scope
- User authentication / login

## Tasks
1. **Backend CORS + port changes** — Add a CORS configuration class to Spring Boot allowing all origins on `/api/**`. Move the backend server port from 5000 to 8080.

2. **Enrich the Dispute entity and CRUD endpoints** — Add fields to the `Dispute` JPA entity to support the dashboard columns: `amount` (BigDecimal), `currency` (String), `merchantName` (String), `dueDate` (LocalDate), `type` (String, e.g. "Processing error"), `enrichmentPercent` (Integer), `imageCount` (Integer), `generatedBy` (String). Add PUT and DELETE endpoints to the DisputeController for full CRUD support.

3. **Seed mock dispute data** — Create a data initializer that populates the database with ~15-20 realistic-looking dispute records on startup if the table is empty, so the dashboard has data to display.

4. **Set up React + Vite frontend with Ant Design** — Initialize a React + Vite project in a `frontend/` directory using **Ant Design (antd)** as the component library and **Axios** for API calls. Configure Vite to proxy `/api` requests to the Spring Boot backend on port 8080, and serve the dev server on port 5000 with host `0.0.0.0`.

5. **Build the dashboard layout** — Create the sidebar navigation and main content shell using Ant Design Layout, Menu, and related components, matching the reference image style (purple/violet accent color, clean white background, professional typography).

6. **Build the disputes table view** — Implement the main disputes table using Ant Design Table with columns, color-coded Tag components for status, Progress bars for enrichment, search/filter bar, category Tabs, and summary stats row. Fetch data from `/api/disputes` via Axios.

7. **Build CRUD UI for disputes** — Add a "Create Dispute" form (Ant Design Modal + Form), inline edit capability, and delete confirmation. Wire these to the backend CRUD endpoints.

8. **Build the dispute detail view** — Add a detail Drawer that opens when clicking "View Details" on a row, showing all dispute fields in a structured layout.

9. **Build Mastercard API integration UI** — Add a section/page for Mastercard API features: connection test status indicator, transaction search form, file dispute form, and claim detail lookup. Wire these to the `/api/mastercard` endpoints.

10. **Build Bulk Enrichment feature** — Add a Bulk Enrichment button and workflow that allows selecting multiple disputes and triggering an enrichment action on them.

11. **Update workflow and deployment** — Reconfigure the workflow to start both the backend (port 8080) and frontend (port 5000). Update deployment config for production build.
